## Specific INT-028 recommendations requested by the coordinator

All are maintainer recommendations for an owner decision, not sign-offs.

1. **When does the new setup start governing?** Last fragment, closure or
   another defined point? Recommend the evidenced closure/valid-takeover
   boundary, including the trusted time packet that seals it. Do not backdate
   to the last fragment; packets in between keep their actual qualification.
2. **What if the comparison target is unresolved?** Recommend permitting a
   new resolved target only when independent valid takeover is established
   by its own reviewed rule. Complete alone is insufficient; without that
   evidence, remain unresolved rather than guess a predecessor.
3. **Must an SRCC=1 update wait for verified F7 event identity?** Choices are
   block, delay or no independent effect on takeover. Recommend the last:
   retain the prominent indeterminate finding and enforce every other
   takeover guard; never claim a verified event from a nearby packet.
4. **What about distributed-mux/nonzero setup channels before 106-11?**
   Per-source governing versus withholding that governing scope? Recommend
   withholding it until a dedicated rule establishes source partitions;
   retain/parse all legacy candidates, not a guessed source-to-data relation.
5. **Which file order?** First fragment or completion? Recommend first
   fragment for candidate order and the separate evidenced takeover boundary
   for governing effect. Inventory order never causes adoption by itself.

**Separate INT-029 decision:** do comment-only/date-only changes count as a
configuration change? A excludes proven descriptive-only changes from semantic
configuration change; B includes them; C requires an explicit reviewed
per-field policy. Recommend A only with reviewed field semantics and no other
change. Always report the raw difference and SRCC claim; do not call it
identical, hide an SRCC=0 discrepancy, infer a reset or select governance.
